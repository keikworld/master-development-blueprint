# Mandatory Documentation Matrix

## Rule

**Documentation is not optional. It ships in the SAME commit as the code it describes. Pre-push agents enforce this.**

If documentation is missing when code changes, the push is blocked. Exception: atomic changes (<50 LOC, no new patterns) skip non-essential docs.

## Full Documentation Inventory

### Per-Session Mandatory (Every Work Session)

| Document | What It Contains | Update When | Example Update |
|----------|-----------------|-------------|----------------|
| `task.md` | Active tasks with timestamps | Every session end | "Completed auth middleware. Started rate limiter. 2026-05-27 14:30 UTC." |
| `planning.md` | Phase %, version, roadmap | Every session end | "Phase 2 at 75%. Version bumped to 1.2.0. Next: rate limiter." |

### Per-Change Mandatory (Based On Change Type Above)

| Document | What It Contains | Update Trigger |
|----------|-----------------|---------------|
| `CHANGELOG.md` | User-facing changes, versions | Any code change visible to users |
| `ARCHITECTURE.md` | System design, module structure | New module, architectural change |
| `LESSONS_LEARNED.md` | Mistakes, solutions, prevention | New insight, bug fix, pattern discovery |
| `DEVELOPMENT_RULES.md` | Coding conventions, rules | New pattern discovered |
| `SECURITY_AUDIT.md` | Vulnerability history | Security fix, audit finding |
| `SECURITY_PATTERNS_REFERENCE.md` | Required security patterns | New security pattern |
| `AGENTS.md` / agent configs | Build commands, check counts | When any fact changes |
| Agent config mirrors (CLAUDE.md etc.) | Agent-specific guidance | When patterns >500 LOC or new commands |

### Per-Decision Mandatory (Governance Records)

| Document | What It Contains | Update Trigger |
|----------|-----------------|---------------|
| Decision log (DECISION-XXX) | Architecture/tech/trade-off decisions | Every decision |
| Risk assessment matrix | Data inventory, threats, mitigations | Every feature >100 LOC |
| Failure/incident log (FAIL-XXX) | Bugs, incidents, root cause, prevention | Every production bug |

### Per-Feature Mandatory

| Document | What It Contains | Update Trigger |
|----------|-----------------|---------------|
| `[FEATURE]_COMPLIANCE.md` | Data handling, legal basis, security | Every new feature |
| API definition (OpenAPI, doc) | Endpoints, params, responses | Every new/modified endpoint |
| Test file | Test coverage for feature | Every new/modified feature |

## Documentation Health Rules

| Rule | Exceptions |
|------|-----------|
| **Same commit** — docs update in same commit as code | Typos, formatting-only changes |
| **No stale docs** — if file hasn't been updated in 90 days, review | Autogenerated files |
| **No orphan docs** — every doc references existing code/files | Planning docs |
| **Co-authored-by on every commit** — human + LLM attribution | None |
| **Risk assessment before code** — for features >100 LOC | Urgent security fixes (add within 24h) |
| **Decision log for every architecture choice** — timestamped | Trivial choices (indentation, variable naming) |
| **Failure log for every production bug** — with prevention | Bugs caught and fixed before deployment |

## Enforcement

Pre-push agent (The Sentry) checks:
```
if code_changed > 0 && (task.md not updated || planning.md not updated):
    BLOCK PUSH

if new_endpoint && (API docs not updated || .env.example not changed when new env vars):
    BLOCK PUSH

if security_fix && (SECURITY_AUDIT.md not updated || LESSONS_LEARNED.md not updated):
    BLOCK PUSH

if architecture_decision && (decision log not updated):
    BLOCK PUSH
```

CI audit checks:
- Every DECISION-XXX number is sequential (no gaps)
- Every FAIL-XXX number is sequential (no gaps)
- No documentation file is >90 days without update
- Documentation matrix matches actual file inventory
